# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MicroPython firmware for an ESP32 (classic ESP-WROOM-32, 4 MB flash, no PSRAM, so about 100 KB of free memory) that turns an Uncle Milton "Moon in My Room" toy into a lamp showing the real current moon phase, with a web page for settings and Wi-Fi setup. Everything in `board/` is copied to the root of the ESP32's filesystem. `README.md` is the user-facing build and setup guide. Keep it in sync when settings, helpers or the page change.

## Running / testing

There is no build, lint or test tooling. The code imports MicroPython-only modules (`machine`, `neopixel`, `network`, `ntptime`) and uses MicroPython APIs (`time.ticks_*`, `asyncio.sleep_ms`, 8-tuple `time.mktime`). It won't run under plain CPython. To test off-device, put stub modules for those four imports first on `sys.path`, patch `time.ticks_ms/ticks_add/ticks_diff`, `time.mktime` and `asyncio.sleep_ms`, then `cd` to a copy of `board/`, set `web.PORT` to a high port and `import main`. Then drive the API with curl.

On the device, use `mpremote` (installed with `uv tool install mpremote`). The board shows up as `/dev/cu.usbserial-*` (CP2102), and Thonny must be closed because it holds the port.

- Deploy: `mpremote connect /dev/cu.usbserial-0001 cp board/main.py board/lamp.py board/net.py board/web.py board/index.html :`
- Run code on the board: `mpremote ... exec "..."`. This interrupts `main.py` with Ctrl-C, so the lamp stops until it is reset.
- Restart and read the start-up output: open the port with pyserial (mpremote's own Python, under `uv tool dir`), pulse RTS, and read for about 20 s. On this board, merely opening the port can also reset it.
- Once the lamp is on Wi-Fi, drive it over HTTP instead (`curl http://moon.local/api/state`). This doesn't interrupt anything.
- Screenshot the page: Playwright's headless Chromium is in `~/Library/Caches/ms-playwright/chromium_headless_shell-*`. Run it with `--headless --screenshot=out.png --window-size=390,900 --virtual-time-budget=5000 http://127.0.0.1:8765/#schedule` against the CPython test server.
- Factory-reset Wi-Fi: delete `settings.json` on the board and reset it.

The README still describes Thonny for end users, where the helpers re-exported by `main.py` (`walk()`, `chamber(j)`, `show(p)`, `demo()`, `startup_sweep()`, `run()`) are called from the Shell after Ctrl-C.

## Architecture

- **Modules.** `main.py` is the asyncio entry point: it starts the Wi-Fi loop, the web server, the start-up sweep, the clock loop and the display loop. `lamp.py` holds the settings, moon maths, LED drawing and what the moon is showing. `net.py` handles joining Wi-Fi, the setup access point with its catch-all name server, scanning and NTP. `sky.py` is pure maths with no hardware imports (calendar, time zone offsets, NOAA sunrise/sunset, the on/off schedule, twilight glow), so it can be tested under CPython or the desktop `micropython`. `themes.py` is also pure: per-chamber RGBW colours for each theme, animated from `time.ticks_ms()`, with modulo done on the integer milliseconds before any float maths. `web.py` is a hand-written HTTP/1.0 server on `asyncio.start_server` plus the JSON API (routes listed at the top of the file). `index.html` is the whole front end in one file, vanilla JS, served from flash in 4 KB chunks. Its main screen is a draggable moon (drag previews via `/api/show`, then Keep sets `FIXED_PHASE`), a power button, brightness, and swatch rows for looks and glows. Detail settings live in full-screen panels (`.sheet`), which can be opened directly with `/#schedule`, `#glow`, `#colour`, `#calibrate`, `#wifi` or `#lamp`. Every settings change auto-saves (`autosave()`, 1.2 s debounce). The page uses system fonts only, because the setup network has no internet.
- **Settings.** The upper-case constants at the top of `lamp.py` are the defaults, and `lamp.SETTINGS` lists the ones that can change at run time. `lamp.apply(dict)` checks every value (raising `ValueError("NAME: reason")`, with nothing changed on error), assigns into the module globals, and calls `rebuild()` if the strip layout changed. `save()` writes to `settings.json` only the values that differ from the defaults, so editing a default in `lamp.py` still takes effect for anything not saved. `unsaved()` compares against what was last loaded or saved. Code elsewhere reads settings as `lamp.NAME` at use time, so never copy one into another module.
- **Derived state.** `strip`, `chambers` and `FEWEST` are worked out in `rebuild()`, which must run after `NUM_LEDS`, `CHAMBERS` or `LED0_ON_LEFT` change (`apply()` does this).
- **What the moon shows.** `lamp.draw()` decides each frame: a web preview set by `hold(kind, value)` (phase, demo, led or chamber, and it expires after `HOLD_S`), otherwise tonight's phase, otherwise `show_setup()` (setup network up, no time yet) or `show_waiting()`. `display_loop()` calls it every 500 ms (40 ms during a demo).
- **Time.** The ESP32 has no time zone data, so `index.html` (`tzRules()`) uses the browser's zone to compute `TZ_RULES`: `[[unix, minutes ahead of UTC], ...]` from 1 January this year, covering 10 years. It saves them automatically when unset, and again each year. Everything in `sky.py` works in whole Unix seconds. `lamp.unix_now()` adds `EPOCH_DELTA` in case the port counts from 2000. Never put Unix times in floats; ESP32 floats are single-precision. Unix times are big ints on the ESP32, which is fine.
- **Schedule and glow.** `lamp.plan()` caches the last and next schedule events and nearby sun events for 60 s. `levels()` returns `(power, glow)` factors that `render()` and `set_chamber()` multiply in. `power` dims the whole moon, `glow` only the dark side. Previews and status signals ignore both. `set_power()` is the hand override; it expires at the next event, capped at `HAND_ON_MAX_S` when turning on during scheduled-off time.
- **Themes and fixed phase.** `render()` and `show_only()` ask `theme_colors()` for a per-chamber colour and pass it to `set_chamber(color=...)`; `None` means the plain `COLOR`. Themes colour only the lit side; the glow stays `DARK_COLOR`. `display_loop` redraws every 40 ms while an animated theme is showing. `FIXED_PHASE` (None or 0.0-1.0) replaces `moon_phase()` in `draw()` and `shown_phase()`. It also renders before the clock is set, though the setup pulse still wins.
- **Phase maths.** `moon_phase()` counts the mean synodic month from a reference new moon. Both references go through `time.mktime`, so the code doesn't depend on the port's epoch. The modulo is done on whole numbers before dividing, because ESP32 floats are single-precision. Keep it that way. `index.html` repeats `lit_fractions` in JS for the on-page moon picture, so change both together.
- **Brightness evening-out.** Every chamber gets the same total light, `GAIN[j] * FEWEST`, split across its LEDs with `divmod`. Pixels are RGBW 4-tuples (`bpp=4`).
- **Wi-Fi.** `net.wifi_loop` opens the open `MoonLamp-XXXX` access point when no Wi-Fi is saved or after `SETUP_AFTER_S` offline, and closes it `SETUP_LINGER_S` after the lamp joins. While phones are on the access point it stops searching for the saved network, because searching changes channel and drops them. A page-started join (`set_wifi`) gets a 30 s grace period from that rule. In setup mode, `web.py` redirects every unknown path to the setup page, and the name server answers every lookup with 192.168.4.1. Together they make phones and Macs pop up the page by themselves. When the page sees the join it shows the new address and calls `/api/setup-done`, which closes the access point `SETUP_CLOSE_S` later; `index.html` counts down the same number. In a normal browser tab, the page then probes the lamp's home IP and moves to `http://<hostname>.local`. The OS pop-up window (macOS Captive Network Assistant and its phone equivalents) can't open links in a real browser and closes when the Wi-Fi changes, so there the user opens the address themselves (we tested this on a Mac). STA power saving is turned off (`pm=PM_NONE`), because it made page loads take about 4 s instead of 0.3 s.
- **Stopping and restarting.** On Ctrl-C, `main.run()` closes the name-server socket and the web server and resets the event loop, so a later `run()` can open port 80 again.

## Constraints

- Real Wi-Fi details live only in `settings.json` on the board (git-ignored). `WIFI_SSID` and `WIFI_PASSWORD` in `lamp.py` stay empty. The API never returns the password.
- Memory is tight. Don't add frameworks or build large responses in memory. Keep `index.html` a single self-contained file and send files in chunks.
- Comments and README text are for hobbyist readers: keep them plain-language.
